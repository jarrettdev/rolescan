# ADR 0019: filters are user configuration

- Status: Accepted
- Date: 2026-11-17

## Context

The source repo carries 29 saved searches and a hardcoded blocked-company list
inside `goals/select-listings`. A redistributed scraper must run the *user's*
searches, and a fresh clone must run before those searches exist.

## Decision

1. `filters/example.json` is the tracked contract; `filters/active.json` is
   generated by `setup.sh`, gitignored and edited by the user.
2. `JOBKIT_FILTERS` overrides the path; with no `active.json` the loader falls
   back to the example, so import and a fixture run never fail for a missing
   file.
3. `blocked_companies` and `title_exclude` are fields in that document. No
   selection preference lives in code.
4. `title_exclude` drops senior titles by default but keeps Graduate, New Grad
   and Intern shapes, so an early-career search works without editing code.
5. `filters/schema.json` (JSON Schema 2020-12) is checked by `doctor.sh`, which
   reports the failing JSON pointer.

## Rules

- **R-filters-are-data**: no lane, company or title preference is hardcoded in
  a goal; `select_listings` takes the blocked set as an argument.

## Check

`python3 tests/test_filters.py` passes; `doctor.sh` exits 1 naming a pointer
when `filters/active.json` violates the schema.
